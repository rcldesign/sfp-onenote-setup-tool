# Changelog

One line per task card, newest first.

## Unreleased

- - M2.4 strip fix: the weeks-remaining strip gives its N numbers equal air between glyph runs (gap = (numberSpan.to - numberSpan.from - sum of the widths) / (N - 1)), so 14 13 12 11 10 no longer run together. 13 numbers keep the printed numberX, and a span too narrow for any gap is an error naming slots.weeksRemaining.numberSpan. Goldens re-recorded: the 90 daily pages moved in synthetic and sfp linux-x64.
- - M6.6 Packaging: build/publish.sh and build/publish.ps1 publish sfp2onenote.exe (91 MB) and sfp2onenote-app.exe (174 MB) as self-contained single-file win-x64 executables into one folder with templates and LICENSE.md, check it, and zip it as sfp2onenote-<version>-win-x64.zip (113 MB). Not trimmed (WPF); symbols and XML docs are left out. .github/workflows/release.yml builds, tests, publishes and attaches the zip on a v* tag. README has new Install and Build from source sections.
- Wave 3 render pipeline: each page's rendered callback runs, and the page is counted, before the page is handed to the writer, so the progress count never lags the pages written and Rendered_callback_counts_pages_as_they_finish no longer races; a page whose callback throws fails like a render failure.
- Wave 3 --group-weeks: the 14 week sections go into one "Weeks" section group (OneNote cftFolder, created once at the first week); the Contents page lists Weeks as a heading over them; the sidecar records the group ID (sectionGroups); Refresh reads grouped notebooks and ignores OneNote's recycle bin.
- Wave 3 --previous: Generate fills the Next quarter link on the previous notebook's quarterly review with a link to the new cover, records the outline ID in the previous state file and updates it in place on later runs; any problem (missing folder or state file, closed or moved notebook, user content over the slot, OneNote refusing the write) is a warning, never a failure, and the summary prints one line saying what happened.
- Wave 3 Time Blocks window: the sidecar records the window the daily pages were generated with (timeBlocks), and Refresh places calendar events and their rows by it (falling back to the Setup page for older sidecars), logging which window it used and noting a different Setup window that will apply at the next Generate.
- M6.5 Refresh tab: RefreshViewModel lists the notebooks INotebookRegistry finds under the known output folders plus the default folder with generated and last-refreshed stamps, runs Preview changes (dry run) listing every PlannedChange with blocked reasons and inked values marked, Refresh now with a reload afterwards, binds "Refresh every day at 05:00" to IScheduledTaskService, and shows the run summary (values read from Setup, pages touched, values and events written, skipped, failed sources, sidecar rebuilt); RefreshView.xaml.
- M6.4 Generate flow: GenerateRunViewModel runs IGenerateOrchestrator on a background thread with progress marshaled to the UI (phase name, n of N), Cancel through the token, a success view (pages written, notebook path, elapsed, Open in OneNote via onenote.exe or the onenote: link, the OneDrive move paragraph with Copy path), a cancelled view and a failure view (phase, page, HRESULT or message, partial notebook note, Save log to a chosen path); GenerateRunView.xaml.
